## Findings

### F1 — Status shows a profile while nothing is loaded

- **Severity:** major
- **Surface:** Status / GPU chip
- **Repro:** After idle or a failed llama load, open Status. Chip `LLAMA · dsc67b` (or similar) with **LLM unloaded**, `llama_up=false`, `tabby_model=null`, VRAM ~200 MiB.
- **Expected:** Chip/status distinguish “last profile” from “loaded and serving”.
- **Actual:** Looks like llama is up. Chat then hits F5/F7.
- **Evidence:** Baseline Status screenshot 16:52 UTC+10; `GET /ui/status` `gpu_mode=llama` `profile=dsc67b` `llama_up=false`. After recovery restart, same shape until `/gpu` loaded an EXL.
- **Likely code:** `tabbyAPI/ui/router.py` status payload; `tabbyAPI/common/llama_runtime.py` `llama_up()`; header chip in `tabbyAPI/ui/static/app.js` / `status.js`.

### F2 — `list models` does not mark the loaded profile

- **Severity:** minor
- **Surface:** Chat
- **Repro:** Send `list models` as the whole message.
- **Expected:** Docs / help text: mark the loaded alias.
- **Actual:** All rows un-marked. Attribution chip still showed the previous GGUF pretty name on a phrase reply.
- **Likely code:** `tabbyAPI/common/phrase_switch.py` `list_text()`.

### F3 — Embedding weights listed as a GPU switch target

- **Severity:** minor
- **Surface:** Chat `list models`
- **Repro:** `list models` includes `Qwen3-Embedding-0.6B | switch to Qwen3-Embedding-0.6B`.
- **Expected:** CPU embeddings stay out of the GPU switch list (AGENTS.md: embedding stays on CPU).
- **Likely code:** `phrase_switch.list_text()` / profile discovery that does not filter embedding folders.

### F4 — Status goes empty mid-switch

- **Severity:** major
- **Surface:** Status / occupancy
- **Repro:** `switch to qwen35`. Poll `GET /ui/status` every 2s.
- **Expected:** `switching=true` and a stable profile/target until ready.
- **Actual:** Several polls with `mode=None profile=None switching=None` (API still 200 or a parse-empty body), then `profile=qwen35 switching=false tabby=None`.
- **Evidence:** QA log at qwen35 t=6s, 8s, 11s.
- **Likely code:** Status handler while Tabby is between containers (`tabbyAPI/ui/router.py` status; `switch_model.py` reload).

### F5 — Switch “done” before Tabby is serving (qwen35 ping)

- **Severity:** blocker
- **Surface:** Chat / GPU switch
- **Model:** qwen35
- **Repro:** `switch to qwen35`, wait until activity/status says loaded / `switching=false`, immediately send a normal prompt.
- **Expected:** First prompt after Loaded uses Qwen3.5-35B.
- **Actual:** 827ms later: `The coding model is not loaded. Switch to an LLM profile from Status, then try again.` Status: `profile=qwen35` `tabby_model=None` `switching=false`.
- **Likely code:** `phrase_switch.llm_not_ready_text` / `switch_in_progress()` (`tabbyAPI/common/phrase_switch.py` ~1712–1752); Status `profile` is last-requested, not `loaded_tabby_name()`. UI Loading bar should stay up until `tabby_model` is set.

### F6 — “Reply with exactly …” is not followed; thinking is concatenated into the answer

- **Severity:** major (UX / eval)
- **Surface:** Chat
- **Models:** qwen, qwen36, gemma, gemma26, glm (all that produced tokens)
- **Repro:** `Reply with exactly: PING-QWEN-OK` (and siblings).
- **Expected:** Assistant bubble is the marker (glm: `12`).
- **Actual:** Long “Thinking Process” / planning text, then the marker. SSE parser sees `reasoning_content` mixed with `content`. Console still shows it as the reply.
- **Likely code:** Console stream assembly in `tabbyAPI/ui/static/chat.js` (`reasoning` vs answer); model thinking defaults in chat sanitizer (`tabbyAPI/ui/manager.py`); glm thinking-only path.

### F7 — `switch to llama` hangs; llama.cpp dies; occupancy never clears

- **Severity:** blocker
- **Surface:** Chat GPU switch
- **Model:** llama / `dsc67b`
- **Repro:** With a GGUF installed, send `switch to llama` as the whole message.
- **Expected:** llama.cpp comes up, `llama_up=true`, SSE ends with Loaded, ping works (slow is OK).
- **Actual:** Phrase SSE stayed open >3 minutes. Host briefly had `llama-server --port 5002` and ~7799 MiB VRAM, then the process was gone (`curl :5002` connection refused). `llama_up` never flipped true (health check on a dead/not-listening server). Stack queue: `Your session is running` on that conversation. Needed `tsctl restart`.
- **Likely code:** `tabbyAPI/common/llama_runtime.py` (`llama_up` GET `/health` timeout 3s); llama start/stop in `switch_model.py`; console job not aborting when llama-server exits (`tabbyAPI/ui/chat.py` `_run_console_job`); lock file `tabbyAPI/switch-model.lock`.

### F8 — Cancel returns ok but does not release the GPU lease

- **Severity:** blocker
- **Surface:** Chat occupancy
- **Repro:** While a llama switch or Code mixed job is in flight, `POST /ui/chat` `{"cancel":true,"conversation_id":…}`.
- **Expected:** Stop ends the flight and frees the stack (comment in `occupancy.py` says this used to wedge chats).
- **Actual:** `{"ok":true}` while `stack_queue.live` stayed true on the same `chat_id`. `_LEASE_MAX_S` is 30 minutes. `abort_flight` only sets `abort_event`; llama/code work may not check it.
- **Likely code:** `tabbyAPI/ui/flight.py` `abort_flight`; `tabbyAPI/ui/chat.py` cancel branch (~358); `tabbyAPI/ui/occupancy.py` `_reclaim_stale` / `_lease_work_live`.

- **Expected:** `data[0].url` keeps `/openai/v1/images/…` (AGENTS.md).

### F11 — Streamed Code `Write` `arguments` can be duplicated JSON objects

- **Severity:** major (browser may already coalesce; raw SSE does not)
- **Surface:** Code tools
- **Repro:** Code Agent turn that emits several Writes. Concatenated `function.arguments` can be `{"path":"about.css"}{"path":"about.css"}`. `json.loads` fails; a naive client posts `{_raw:…}` and gets `path is required`.
- **Expected:** One JSON object per tool call.
- **Actual:** First Code attempt: four Writes failed `path is required`. Round 3 explicitly showed doubled JSON. Retry with `JSONDecoder.raw_decode` succeeded.
- **Likely code:** tool-call delta assembly in the OAI stream (`tabbyAPI/endpoints/OAI/`); browser `normalizeToolCalls` in `tabbyAPI/ui/static/chat.js` (~12320). Confirm the live UI still merges deltas correctly.

### F12 — Mixed image job enters `writing_code` even when Writes fail; leftover job stays `coding`

- **Severity:** major
- **Surface:** Code + images
- **Repro:** First Code workspace `qa-site-1789284939`: tools failed, but SSE already contained `tabby-image-job: 0b83fc89-…`. Status `job.status=coding` `phase=writing_code` after cancel. Second workspace got a **new** id `469817a7-…` (did not steal the leftover — good).
- **Expected:** No Comfy job until Writes succeed; abandon leftover jobs on cancel; never attach another chat’s job.
- **Likely code:** `tabbyAPI/images/chat.py` `_page_blocking_comfy` / job create; `tabbyAPI/images/jobs.py` `writing_code`.
